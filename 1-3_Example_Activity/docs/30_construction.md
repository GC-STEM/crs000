# 1-3 Higher/Lower Game | Software Construction Plan

**Status:** Instructor-provided guidance.

## Purpose and Scope

Implement your own design in [`src/high_low.py`](../src/high_low.py), the
activity's sole required deliverable.

## Construction Inputs

Use the [requirements](10_requirements.md), [design guidance](20_design.md), and your own planning notes.

## Development Environment

Open the whole course repository in VS Code locally or in Codespaces. Use
Python 3.12. Keep the supplied import, function wrapper, and main guard.
Use variables, input/output, integer conversion, decisions, and while loops;
no additional functions or classes are required.

## Construction Approach

Choose one small behavior to implement. Predict its result, run it, and
compare the result with the requirement before adding more. Resolve a syntax
or logic problem before building on that code.

Write a brief module docstring describing your program's purpose, inputs,
processing, and outputs in your own words. Use meaningful names and consistent
four-space indentation. Cite sources you use in the References comments.

## Run the Program

From the **repository root**:

```bash
python 1-3_Example_Activity/src/high_low.py
```

If the environment names its Python 3.12 command `python3`, use that instead.
The supplied unfinished starter exits without playing a game.

## Version Control and Change Management

Save your files and use the course's existing Git workflow for your personal
repository. Review changes before committing. Do not alter instructor tests
or requirements to make your program appear correct.

## Construction Quality Gates

- All required behavior is implemented and reviewed against the requirements.
- The program runs, and required manual cases have been checked.
- Starter TODO prompts in the submitted source have been resolved.
- Comments, docstrings, and source acknowledgements accurately reflect your work.
- You can explain the code and the results you observed.

## Testing and Handoff

Use [the test plan](40_testing.md). Automated checks cover selected behavior;
manual testing and review remain necessary. Follow your instructor's directions
if this demonstration is assigned. No deployment or publishing step is required.
